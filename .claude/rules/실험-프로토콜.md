# 실험 프로토콜

> evals/ 또는 experiments/ 작업 시 적용되는 규칙.
> 루트 CLAUDE.md의 "기록 = 실행", "변경에는 맥락이 따라다닌다" 원칙의 실험 도메인 구현.
> 상세 파이프라인 규칙(실행 모드, fixture, 결과 JSON 스펙)은 `evals/CLAUDE.md` 참조.

---

## 규칙

1. **환경 확인** — 실험 실행 전, 현재 환경(config, .env, 프롬프트 버전, fixture 상태)이 의도한 조건과 일치하는지 확인받는다. `.env`가 `config.py`를 오버라이드하므로 코드만 보면 안 된다.

2. **변수 격리** — 한 번에 하나만 바꾸고 나머지는 고정. 여러 변수를 동시에 바꾸면 원인 특정이 불가.

3. **config 복원** — 실험용으로 변경한 config, .env, prompts는 완료 후 baseline으로 되돌린다.

4. **결과 보존** — `evals/results/`의 JSON은 삭제하지 않는다. 실험 이력이 비교의 기반.

5. **fixture 수동 편집 금지** — 스크립트가 자동 생성. 수동 편집하면 fingerprint가 깨진다.

6. **프롬프트 버전 관리** — `app/prompts.py`에 새 버전 등록 + `CURRENT_*_VERSION` 갱신. 하드코딩 수정 금지.

## 실험 전/중/후 질문

### 실험 전

- baseline 측정값이 존재하는가?
- 변경하려는 변수가 정확히 하나인가?
- fixture 의존성 체인을 확인했는가? (changed 범위 밖 upstream이 필요하지 않은가?)

### 실험 중

- 이 파라미터 선택의 근거를 남겼는가? (--label, 커밋 메시지)
- config snapshot이 실제 실행값과 일치하는가?

### 실험 후

- config/환경이 baseline으로 복원됐는가?
- 결과가 기대 범위 밖이라면, 원인 가설을 남겼는가?
- 이 변경이 다른 stage의 fixture를 무효화하는가?

## 냄새 신호 (실험 특화)

- fixture 생성 시점이 현재 config와 어울리지 않는다 → **config drift**
- 결과 JSON의 config ≠ 현재 config.py → **snapshot 양다리**
- qa_results에 context_text가 비어있다 → **retrieval 실패** 또는 media_id 누락
- latency가 이전 대비 2배 이상 → 모델/네트워크 변경 확인
- n=1 실험으로 결론 내리려 한다 → 질문 5개 이상 필요 (LLM 분산)
