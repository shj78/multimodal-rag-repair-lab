# Entry Task: 정량 베이스라인 측정

> **이 작업은 Weekend-1 Day 0에서 새 페어와 함께 수행합니다.** Prework에서 미리 할 필요는 없습니다.

이번 스프린트의 모든 Before/After 비교의 기준이 되는 **Before 베이스라인**을 측정합니다. 엣지 케이스가 실제로 실패하는지 직접 확인하는 것이 목적입니다.

---

## Track A: RAG 베이스라인

테스트 질문 **5~10개를 수동으로 실행**합니다. 반드시 아래 카테고리별로 질문을 포함하세요.

### 필수 질문 카테고리

| 카테고리 | 질문 수 | 목적 |
|---------|---------|------|
| 테이블 질문 | 2~3개 | PDF 테이블 데이터에 대한 질문 → 현재 실패 확인 |
| 이미지/차트 질문 | 2~3개 | PDF 이미지·차트에 대한 질문 → 완전 실패 확인 |
| 문서에 없는 질문 | 2~3개 | 환각 답변 여부 확인 |

### 질문 예시

```
[테이블] "보고서 3페이지 표에서 2024년 매출 합계는?"
[테이블] "가장 높은 성장률을 기록한 분기는?"
[이미지] "보고서의 차트에서 가장 높은 막대의 수치는?"
[이미지] "그래프에서 2023년과 2024년의 추세 차이는?"
[환각]   "이 보고서에서 CEO의 취미는?"
[환각]   "2025년 예상 매출은?" (2024년까지만 포함된 문서)
```

### 측정 방법

1. 테이블/이미지가 포함된 PDF를 업로드
2. 각 질문을 수동으로 실행
3. **질문, 시스템 답변, 판정(성공/실패/환각)**을 기록

Track A 스타터 평가 스크립트(`docs/00-shared/eval.py`)를 활용하면 자동화할 수 있습니다.

### 기록 템플릿

| # | 카테고리 | 질문 | 시스템 답변 (요약) | 판정 |
|---|---------|------|------------------|------|
| 1 | 테이블 | | | 성공/실패/환각 |
| 2 | 이미지 | | | |
| 3 | 환각 | | | |
| ... | | | | |

## Track B: 멀티모달 베이스라인

기존 `evaluation_utils.py`로 **자동 측정**을 먼저 수행하고, 추가로 **엣지 케이스 질문을 수동 테스트**합니다.

### 자동 측정

`evaluation_utils.py`를 실행하여 기존 지표(Answer Relevance, Groundedness, Retrieval Precision, WER)를 기록합니다.

### 수동 엣지 케이스 테스트

| 카테고리 | 질문 수 | 목적 |
|---------|---------|------|
| 화면 정보 질문 | 2~3개 | 화면에만 보이는 내용 → 완전 실패 확인 |
| 숫자/고유명사 검색 | 2~3개 | 전사 불일치로 검색 실패 확인 |

### 질문 예시

```
[화면]   "영상에서 보여준 함수 이름은?"
[화면]   "슬라이드에 나온 매출 수치는?"
[숫자]   "삼천이백만원은 얼마인가?" → "3,200만원"으로 검색
[고유명사] "React hooks에 대해 설명한 부분은?" → 전사가 "리액트 훅스"인 경우
```
