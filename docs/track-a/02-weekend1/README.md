## 구현 모듈 (4 핵심 + 2 선택)

> 아래 4개 핵심 모듈 중 **완주 스토리 1개를 선택**하여 Before/After를 데모할 수 있을 만큼 완성합니다. 추가 모듈 1개를 권장하되, **4개 전부를 구현할 필요는 없습니다**.

- 모듈 간 의존성이 없으므로 관심 있는 것부터 시작합니다
- **완주 스토리 추천: 모듈 1(PDF 테이블 파싱)** — 스프린트 2 (RAG)에서 가장 많이 보고한 문제이며, Before/After 차이가 극적입니다
- **모듈 1+2 통합 안내**: 모듈 1(테이블)과 모듈 2(이미지)는 같은 PDF 처리 파이프라인을 수정합니다. 모듈 1을 완주 스토리로 선택하면 모듈 2를 추가 모듈로 확장하기 수월합니다 (같은 코드 경로에서 테이블 감지 → 이미지 감지를 순서대로 추가)

### 핵심 모듈 1: PDF 테이블 파싱

**엣지 케이스**: PDF에서 테이블이 포함된 페이지를 텍스트로 추출하면, 행/열 구조가 깨져서 **의미 없는 텍스트 조각**이 됩니다.

**재현 테스트**:
- "PDF 3페이지 표에서 2024년 매출 합계는?" → 깨진 텍스트로 **오답 또는 환각**
- "보고서에서 가장 높은 성장률을 기록한 분기는?" → 수치 비교 불가로 **실패**

**구현 목표**:
- `pdfplumber` 또는 `camelot`으로 테이블 구조를 감지하고 마크다운 형식으로 변환
- 변환된 마크다운 테이블을 청크로 저장하여 검색에 활용

> 참고: [`reference.md` 섹션 5](../../00-shared/reference.md#track-a-5-pdf-테이블-파싱)

**DoD**:
- [ ] 테이블이 포함된 PDF를 업로드했을 때, 테이블 데이터가 마크다운으로 `document_chunks`에 저장됨
- [ ] 테이블 내 수치에 대한 질문에서 정확한 답변을 얻을 수 있음
- [ ] 다양한 테이블 형태(2x3, 5x10 등)에서 파싱이 동작함

---

### 핵심 모듈 2: PDF 이미지/차트 추출 (Vision)

**엣지 케이스**: PDF에 포함된 이미지, 차트, 그래프는 텍스트 추출 시 **완전히 무시**됩니다.

**재현 테스트**:
- "보고서 5페이지 차트에서 가장 높은 막대의 수치는?" → **완전 실패**
- "그래프에서 2023년과 2024년의 추세 차이는?" → **완전 실패**

**구현 목표**:
- PDF 페이지에서 이미지 영역을 감지하고 추출
- Vision 모델(`gemma3` 또는 `gpt-4o`)로 이미지 내용을 텍스트로 설명
- 설명 텍스트를 페이지 번호와 함께 검색 가능한 청크로 저장

> 참고: [`reference.md` 섹션 6](../../00-shared/reference.md#track-a-6-pdf-이미지차트-인식)

**DoD**:
- [ ] 이미지/차트가 포함된 PDF 업로드 시, 이미지 설명이 자동으로 `document_chunks`에 저장됨
- [ ] 차트/그래프에 대한 질문에서 관련 답변을 얻을 수 있음
- [ ] Before에서 완전 실패한 동일 질문으로 검증하여 After에서 성공함

---

### 핵심 모듈 3: Hybrid Search 구현

**엣지 케이스**: 벡터 시맨틱 검색만으로는 **정확한 키워드 일치**가 필요한 질문에서 관련 청크를 놓칩니다.

**재현 테스트**:
- "GDP 성장률이 언급된 부분은?" → 벡터 검색이 "경제 성장"은 찾지만 **"GDP" 정확 일치 누락**
- "섹션 3.2의 내용을 요약해줘" → "3.2"라는 정확한 텍스트를 벡터만으로 **매칭 실패**

**구현 목표**:
- BM25 키워드 검색 + 벡터 시맨틱 검색을 결합
- **한국어 BM25 필수**: `kiwipiepy` 형태소 분석기를 사용하여 토큰화
  - macOS 설치: `pip install kiwipiepy` (별도 시스템 의존성 없음)
  - 사용법: `from kiwipiepy import Kiwi; kiwi = Kiwi(); tokens = [t.form for t in kiwi.tokenize(text)]`

> 참고: [`reference.md` 섹션 7](../../00-shared/reference.md#track-a-7-hybrid-search-원리)

**DoD**:
- [ ] `/qa` 엔드포인트가 키워드 검색과 벡터 검색 결과를 결합하여 반환함
- [ ] 키워드 정확 일치 질문에서 Before(벡터만) 대비 Retrieval Precision이 향상됨
- [ ] 시맨틱 유사 질문에서 성능이 유지되거나 향상됨

---

### 핵심 모듈 4: 환각 방지 (안전 응답)

**엣지 케이스**: 사용자가 **문서에 존재하지 않는 내용**을 질문하면, 시스템이 답변을 **그럴듯하게 지어냅니다** (환각).

**재현 테스트**:
- "이 보고서에서 CEO의 취미는?" → 시스템이 **환각 답변** 생성
- "2025년 예상 매출은?" (문서가 2024년까지만 포함) → **추측 답변** 생성

**구현 목표**:
- 검색 결과 유사도가 낮으면 **"문서에 해당 정보가 없습니다"** 거부 응답
- 또는 LLM 프롬프트에 "근거 없으면 반드시 거부" 규칙 강화
- 과도한 거부(정상 질문까지 거부)를 방지하는 트레이드오프 조정

> 참고: [`reference.md` 섹션 8](../../00-shared/reference.md#track-a-8-환각-방지-전략)

**DoD**:
- [ ] 문서에 없는 내용에 대한 질문 5개 중 4개 이상에서 적절히 거부함
- [ ] 기존에 정상 답변하던 질문들의 정확도가 Before 대비 떨어지지 않음
- [ ] Before(환각 답변) vs After(적절한 거부)를 수동 검증으로 비교

## 선택 구현 모듈

시간이 남으면 아래 모듈에 도전하세요.

### 선택 모듈 5: HyDE 또는 Query Rewriting

사용자 질문을 LLM이 **가상 답변**으로 확장하거나, **검색에 최적화된 형태**로 변환하여 검색 정밀도를 높입니다.

### 선택 모듈 6: Cross-encoder Re-ranking

벡터 검색 Top-k 결과를 Cross-encoder 모델로 **재정렬**하여, 가장 관련 높은 청크를 상위로 올립니다.
