# Track B: Weekend-1 — 멀티모달 고도화

## Weekend-1 전반부: 혼합 프로바이더 셋업 + 코드 파악 (반나절)

Weekend-1의 **전반부**를 혼합 프로바이더 셋업과 코드 파악에 할애합니다. 이것은 모듈이 아니라 **환경 설정 단계**입니다.

### 단계 1: 코드 파악 (30~60분)

1. **인수인계 Q&A**: 새 페어가 인수인계 문서를 읽고 질문
2. **함께 서버 실행**: 화면에 슬라이드/코드가 표시되는 영상 업로드 → Q&A 1회 실행하여 현재 동작 확인

### 단계 2: 혼합 프로바이더 리팩토링 (1~2시간)

[`reference.md` 섹션 4](../../00-shared/reference.md#공통-4-혼합-프로바이더-패턴)를 참고하여 `EMBED_PROVIDER`/`CHAT_PROVIDER` 분리를 수행합니다.

**`bge-m3`(1024d) 임베딩 모델로 전환합니다. 이 전환은 필수입니다** — `nomic-embed-text`의 한국어 유사도 압축 문제가 이후 모든 모듈의 검색 품질에 영향을 줍니다.

> 스프린트 3 (멀티모달)에서 이미 `bge-m3`로 전환한 팀은 이 단계를 빠르게 확인만 하고 넘어갑니다.

**DB 마이그레이션 절차**:
1. Supabase 대시보드의 **SQL Editor**에서 임베딩 컬럼의 차원을 `vector(768)` → `vector(1024)`로 변경합니다. 테이블명과 컬럼명은 본인 프로젝트에 맞게 확인하세요
2. **Table Editor** 또는 SQL Editor에서 `match_segments` RPC 함수의 차원 파라미터도 `1024`로 수정합니다
3. 기존 데이터를 삭제한 뒤 테스트 미디어 1개를 재업로드하여 정상 동작을 확인합니다
4. (전체 재임베딩은 테스트 미디어 1~2개로 충분 — 모든 기존 데이터를 재처리할 필요 없음)

### 단계 3: 베이스라인 측정 (30분)

- Before 상태의 엣지 케이스를 실제로 재현 (화면 정보, 숫자/고유명사, 0건 검색, 거부 0점) — 상세 가이드는 [`entry-task.md`](../../01-prework/entry-task.md) 참고
- 스프린트 3 (멀티모달) 프로젝트에 포함된 **기존 `evaluation_utils.py`**로 Before 베이스라인 자동 측정
- `assets/track-b/test_questions.json`은 수동 엣지 케이스 테스트의 참고용으로 활용하세요

### 셋업 DoD

- [ ] `bge-m3` 임베딩 + `gpt-4o-mini` 채팅 조합에서 Q&A가 정상 응답함

## Weekend-1 후반부: 모듈 구현 시작

### 핵심 모듈 1: 화면 정보 추출 (VLM 프레임 분석)

**엣지 케이스**: 영상에서 슬라이드, 코드, 차트, 자막이 **화면에만 표시**되고 말로는 설명하지 않는 경우, STT 전사에는 해당 내용이 전혀 없으므로 검색이 불가능합니다.

**재현 테스트**:
- "영상에서 보여준 함수 이름은?" → **완전 실패**
- "슬라이드에 나온 매출 수치는?" → **완전 실패**

**구현 목표**:
- 영상에서 일정 간격으로 프레임을 샘플링
- VLM(`gemma3` 또는 `gpt-4o`)으로 각 프레임의 화면 내용을 텍스트로 변환
- 변환된 텍스트를 타임스탬프와 함께 검색 가능한 세그먼트로 저장

**단계적 접근 (권장)**:
1. 먼저 **2분 이하의 짧은 영상**으로 파이프라인을 검증 (프레임 수가 적어 빠르게 반복 가능)
2. 초기 샘플링 간격은 **10~15초**로 넉넉하게 시작 (5초 간격은 처리 시간이 길어짐)
3. 파이프라인이 동작하면 전체 영상에 적용
4. `gemma3`로 먼저 테스트하고, 품질이 부족한 경우에만 `gpt-4o`로 비교

> 참고: [`reference.md` 섹션 9](../../00-shared/reference.md#track-b-9-vlm-프레임-분석과-멀티모달-검색)

**DoD**:
- [ ] 영상 처리 시 프레임 샘플링 + VLM 설명 추출이 자동으로 수행됨
- [ ] 화면에만 보이는 정보에 대한 질문에서 관련 답변을 얻을 수 있음
- [ ] Before에서 완전 실패한 동일 질문으로 검증하여 After에서 성공함

### 핵심 모듈 2: 전사-검색 불일치 해결 (STT 후처리)

**엣지 케이스**: STT가 음성을 텍스트로 변환할 때 숫자와 고유명사가 **검색 불가능한 형태**로 기록됩니다.

**재현 테스트**:
- 발표자: "삼천이백사십오억원" → 검색: "3,245억" → **불일치로 실패**
- 발표자: "React 훅스" → 전사: "리액트 훅스" → 검색: "React hooks" → **실패**

**구현 목표**:
- STT 출력에 후처리 파이프라인을 추가하여 숫자를 정규화
- 기술 용어 사전 매핑 적용
- 정규화된 텍스트를 원본과 함께 저장하여 검색 범위 확대

**현실적 범위 설정**:
- 한국어 숫자 정규화는 완벽하게 구현하기 어렵습니다. **자주 나오는 패턴 5개** (천, 백, 만, 억 + 조합)를 처리하는 것을 목표로 합니다
- `korean-number` 패키지가 있으면 활용하고, 없으면 정규식으로 핵심 패턴을 직접 구현합니다
- 기술 용어 사전은 **5~10개 핵심 용어**부터 시작합니다 (React, API, GPU 등)

> 참고: [`reference.md` 섹션 10](../../00-shared/reference.md#track-b-10-stt-후처리-파이프라인)

**DoD**:
- [ ] 숫자 표현이 한글/아라비아 숫자 모두로 검색 가능
- [ ] 주요 기술 용어(5개 이상)가 한글/영문 모두로 검색 가능
- [ ] Before에서 불일치로 실패한 질문 중 70% 이상이 After에서 검색 성공

---

### 핵심 모듈 3: 동적 Threshold

**엣지 케이스**: 고정 `similarity_threshold`로 인해 일부 질문에서 검색 결과가 0건 반환되어 환각이 발생합니다.

**재현 테스트**:
- 특정 질문 → 검색 결과 0건 → 시스템이 환각으로 엉뚱한 답변 생성

**구현 목표**:
- 고정 threshold 대신 "최소 N개 결과 보장" 또는 분포 기반 컷오프 적용
- 0건 발생률 Before 대비 50% 이상 감소

> 참고: [`reference.md` 섹션 3](../../00-shared/reference.md#공통-3-동적-threshold) · [섹션 11 (Track B 적용 가이드)](../../00-shared/reference.md#track-b-11-동적-threshold--track-b-적용-가이드)

**DoD**:
- [ ] 0건이 반환되던 케이스에서 관련 세그먼트가 반환됨
- [ ] 무관한 세그먼트 노이즈가 Before 대비 악화되지 않음
- [ ] Before 0건 질문 목록과 After 결과를 수치 비교한 표 작성

### 핵심 모듈 4: LLM-as-Judge 개선

**엣지 케이스**: LLM Judge가 올바른 거부 응답을 0점으로 평가하여, 정상 동작이 실패로 기록됩니다.

**재현 테스트**:
- 영상에 없는 내용 질문 → 시스템이 적절히 거부 → Judge가 0점 부여

**구현 목표**:
- `calculate_answer_relevance()`에 `context` 파라미터 추가
- 평가 프롬프트에 등급별 기준 + 동의어 추론 규칙 추가

> 참고: [`reference.md` 섹션 12](../../00-shared/reference.md#track-b-12-llm-as-judge-개선-전략)

**DoD**:
- [ ] 올바른 거부 응답이 ≥ 0.7 점수를 받음
- [ ] 동일 질문셋 3회 반복 측정 시 평균 점수 분산이 감소함
- [ ] 수동 검증 5문항과 Judge 점수 간 일치율이 향상됨
