## T1 — 비전질문

**쿼리:** 영상에서 사용된 파이썬 내장 함수를 모두 나열해줘

| 항목 | correction OFF | correction ON |
|------|---------------|--------------|
| **답변** | `input()`, `split()`, `int()`, `len()` | `input()`, `split()` — `int()`, `len()` 누락 |
| **AR / GR / RP** | 1.00 / 1.00 / 0.00 | 0.90 / 0.70 / 0.00 |

**context_text (OFF)** — 검색 청크: `[30s]` `[45s]` `[60s]`

> [30s] 그 문자열을 쪼개는 방법이 있습니다 바로 그 문자열에다가 점스플릿이라고 하는 겁니다...
> `[비전][코드]` input("점을 쉼표 구분된 점수로 입력하세요"), score_list.split(",")
> `[키워드]` input, split, 리스트, 점수
>
> [45s] 스플릿이 쪼갠다 나눈다는 뜻이잖아요...
> `[키워드]` input, split, 리스트, 평균, 점수
>
> [60s] 쉼표로 자를 거다라는 얘기예요...
> `[키워드]` input, split, 리스트, 평균, 점수 | total, score_list, int, average, len, for

**context_text (ON)** — 검색 청크: `[75s]` `[30s]` `[60s]`

> [75s] 그 다음에 그 각각을 숫자로 우리가 변환을 하면 되는 겁니다
> `[비전][코드]` total = 0 / for score in score_list: total += int(score) / average = total / len(score_list)
> `[음성 전사 원문]` 더하면 쉽습니다 우리 더한 거는 폴루프로 사용해가지고...
> `[키워드]` total, score_list, int, average, len, for, +=, /
>
> [30s] 그 문자열을 쪼개는 방법이 있습니다...
> `[키워드]` input, split, 리스트, 점수
>
> [60s] 점수를 쉼표로 구분하여 입력하세요 (예: 85,90,78): 점스플릿 한 다음에...
> *(교정: 실행 화면 문자열이 전사 앞에 삽입됨)*
> `[키워드]` input, split, 리스트, 평균, 점수 | total, score_list, int, average, len

**비고:** OFF는 [30s][45s][60s](input/split 구간)를 검색해 `int`, `len`까지 포함한 정답 도출. ON은 교정 후 [75s](total 계산 구간)가 상위 청크로 올라와 `int`, `len` 누락. 검색 구간 이동이 답변 완성도를 낮춤.

## T2 — 비전질문

**쿼리:** total 변수의 초기값은 무엇인가?

| 항목 | correction OFF | correction ON |
|------|---------------|--------------|
| **답변** | total 변수의 초기값은 0 (근거: [90s]) | total 변수의 초기값은 0 (근거: [90s] `total = 0` 명시) |
| **AR / GR / RP** | 1.00 / 0.70 / 0.00 | 1.00 / 0.90 / 0.67 |

**context_text (OFF)** — 검색 청크: `[90s]` `[75s]` `[105s]`

> [90s] 인트 이렇게 정수형으로 바꿔준 다음에 더해주면 되겠죠 그 다음에 마지막으로는 그 길이만큼 랜이라는 거는 어떤 리스트가 있을 때...
> `[비전][코드]` total = 0 / for score in score_list: total += int(score) / average = total / len(score_list)
> `[화면텍스트]` 코딩 늘이토로 배우는 창촌보 파일선 진행률 82% *(OCR 오류 포함)*

**context_text (ON)** — 검색 청크: `[90s]` `[105s]` `[75s]`

> [90s] 인트 이렇게 정수형으로 바꿔준 다음에 더해주면 되겠죠 그 다음에 마지막으로는
> `[비전][코드]` total = 0 / for score in score_list: total += int(score) / average = total / len(score_list)
> *(교정: 코드 블록이 전사 중간에 직접 삽입됨)*
> 그 리스트의 길이를 가져오는 걸 len이라고 합니다. 랭프의 줄임말이죠...
> `[키워드]` total, score, score_list, average, int, len, for, python

**비고:** correction ON에서 전사에 코드 블록이 삽입되어 `total = 0`이 명시적으로 검색됨. RP 0.00 → 0.67, GR 0.70 → 0.90으로 correction 효과가 가장 명확하게 드러난 질문.

## T3 — 비전질문

**쿼리:** 영상 실행 화면에서 직접 입력한 숫자들은 무엇인가?

| 항목 | correction OFF | correction ON |
|------|---------------|--------------|
| **답변** | 85, 90, 78 (근거: [165s]) | 85, 90, 78 (근거: [135s]) |
| **AR / GR / RP** | 0.70 / 0.40 / 1.00 | 0.70 / 0.30 / 1.00 |

**context_text (OFF)** — 검색 청크: `[180s]` `[135s]`

> [180s] 이렇게 해서 78점 89점 95점 이렇게 3개를 넣어볼까요...
> `[비전][코드]` score_list = user_input_scores.split(" ") *(split(" ") 오기재)*
> total = 0 / for score in score_list: total = int(score) *(`+=` 누락 오기재)*
> `[실행결과]` 입력한 점수들의 평균은: 87.8
> `[화면텍스트]` 점수를 쉼표로 구분하여 입력하세요 (예: 85,90,78): 85,90,78 / 입력한 점수들의 평균은: 84.333...
>
> [135s] 70점 80점 90점 100점 99점 → 평균은 87.8이다...
> `[비전][코드]` 전체 코드 포함, split(",") 올바름
> `[실행결과]` 85,90,78 → 84.333...

**context_text (ON)** — 검색 청크: `[180s]` `[165s]` `[135s]`

> [180s] 이렇게 해서 78점, 89점, 95점 이렇게 3개를 넣어볼까요
> *(교정: 숫자 뒤 쉼표 추가)*
> `[비전][코드]` 동일 — split(" "), total = int(score) 오기재 유지
> `[실행결과]` 입력한 점수들의 평균은: 87.8
>
> [165s] 78점, 89점, 95점 이렇게 3개를 넣어볼까요
> *(교정: 쉼표 추가)*
>
> [135s] 70점 맞았고, 80점 맞았고, 90점, 100점, 99점...
> *(교정: 숫자 나열에 쉼표 추가)*

**비고:** 두 실험 모두 RP=1.00으로 검색 성공. OFF는 GR 0.40, ON은 GR 0.30으로 오히려 하락. ON의 전사 교정이 음성 자연어("78점 89점 95점")에 불필요한 쉼표를 추가하고, gold answer인 "70,80,90,100,99" 대신 "85,90,78"을 반환하는 방향으로 과교정된 것으로 추정.

## T4 — 단순사실

**쿼리:** 점수를 입력받을 때 사용한 구분자는 무엇인가?

| 항목 | correction OFF | correction ON |
|------|---------------|--------------|
| **답변** | 쉼표(,) — `split(",")` 코드 인용 (근거: [45s]) | 쉼표 — `split(",")` 코드 인용 없음 (근거: [30s][45s]) |
| **AR / GR / RP** | 1.00 / 1.00 / 0.67 | 0.70 / 0.70 / 0.67 |

**context_text (OFF)** — 검색 청크: `[45s]` `[30s]` `[60s]`

> [45s] 스플릿이 쪼갠다 나눈다는 뜻이잖아요...구분자 내가 이걸로 문자열을 자를 거다...
> `[비전][코드]` input("점수를 쉼표로 구분하여 입력하세요 (예: 85,90,78): ") / score_list.split(",")
> `[키워드]` input, split, 리스트, 평균, 점수
>
> [30s] 그 문자열을 쪼개는 방법이 있습니다...
> `[비전][코드]` split(",")
>
> [60s] 쉼표로 자를 거다라는 얘기예요...

**context_text (ON)** — 검색 청크: `[45s]` `[30s]`

> [45s] 점수를 쉼표로 구분하여 입력하세요 (예: 85,90,78): 점스플릿 한 다음에...
> *(교정: input() 실행 프롬프트 문자열이 전사 앞에 삽입됨)*
> `[비전][코드]` split(",")
> `[키워드]` input, split, 리스트, 평균, 점수
>
> [30s] 그 문자열을 쪼개는 방법이 있습니다...
> `[비전][코드]` split(",")

**비고:** ON에서 [45s] 전사에 input() 실행 화면 문자열이 삽입되어 전사와 코드가 뒤섞임. 답변은 "쉼표"를 맞히지만 `split(",")` 코드 인용 없이 AR 1.00 → 0.70 하락. correction 프롬프트의 "화면과 무관한 설명 문장은 원문 유지" 지시가 지켜지지 않은 케이스.

## 종합 분석

### correction이 효과적이었던 케이스

- **T2 (total 초기값):** 전사에 코드 블록이 삽입되어 `total = 0` 직접 검색 가능. RP 0.00 → 0.67, GR 0.70 → 0.90.

### correction이 역효과를 낸 케이스

- **T1 (내장 함수 나열):** 교정 후 검색 청크가 [30s][45s] → [75s]로 이동. `int`, `len`이 포함된 청크 대신 total 계산 청크가 상위에 올라와 답변 누락.
- **T3 (입력 숫자):** 음성 자연어("78점 89점 95점")에 불필요한 쉼표 삽입으로 GR 0.40 → 0.30.
- **T4 (구분자):** input() 실행 화면 문자열이 전사 앞에 삽입되어 텍스트 혼재. AR 1.00 → 0.70.

### 원인 가설

correction 프롬프트 v1이 "화면과 무관한 설명 문장은 원문 유지" 지시를 충분히 강제하지 못함.
특히 input() 실행 결과처럼 **화면에 뜨는 텍스트가 음성 설명 중간에 삽입**되는 과교정 패턴이 반복됨.

### 개선 방향

- correction 프롬프트에 "음성 전사 문장의 순서·구조는 변경하지 않는다" 제약 추가
- "코드 실행 결과 문자열(print 출력)을 전사 본문에 삽입하지 않는다" 명시
- 과교정 방지를 위한 few-shot 예시 추가 검토
